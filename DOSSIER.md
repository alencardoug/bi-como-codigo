## 7. Where I hesitated

Decisions that could have gone the other way, with the reason they went this one.

- **Exact totals keys** (§3) instead of allowing extra keys the gate ignores: an ignored key is an
  unchecked value inside the package; 2.4 changes the rule in a protected PR.
- **The live read in `verify`** rather than in `promote` (which has a credential and runs later): the
  live comparison is about reuse, `verify` has no credential and the data is public, and §5 argues
  the gap is closed by `decide` conditions 1 and 4. If the argument fails, the check belongs in
  `promote` too.
- **A live envelope no declared password opens fails the gate** instead of being skipped: skipped is
  not verified; the cost is that a password change would need its own decision (N22 fixes them).
- **The value thresholds of §6** (12 characters, 6 characters): a guess to keep honest pages from
  failing; below them a value is not searched. The real labels arrive at 2.4.
- **Real PRs for only three mutations** (§9.3), the rest in `make check`, since `verify` is the same
  function in both; 2.2's T6 already proved the workflow path for two mutations.
- **`duckdb==1.5.6`, not 2.0.0**: 2.0.0 is sixteen days old and a major version; 1.5.6 is the last of
  the mature line. DuckDB-WASM's version is chosen at 2.3.
