## 7. Where I hesitated

Decisions that could have gone the other way, with the reason they went this one.

- **The oracle is the gate's `verify`, not a search of its own** (§2.5, §8): it means a candidate's
  output must already fit the gate's inclusion list and media types — strict, and possibly failing a
  candidate for a reason unrelated to clear data (a `manifest.json` of its own, a
  `sourceMappingURL` comment). I kept it because whatever is chosen must pass that same function in
  2.5. The criterion speaks only of clear data at build time, so §2.5 splits the refusals: by
  content fails the criterion; by form is a cost cleared by a build setting, and fails only if no
  setting clears it. Whether that split leaves a hole — a leak that shows up only as a form
  refusal, and is then "cleared" — is worth a look.
- **Vega-Lite for the own build** (§4): it could equally be ECharts, which makes the charts
  comparable with Evidence's. A choice the Owner may overturn.
- **An invented fixture with P01's real columns** rather than reading the real view: real data
  needs 2.4's source gate; invented values keep "no report data before 2.4".
- **Prototypes tracked in the repository, outside `make check`** (§5): their npm dependencies would
  make the gate slow and network-bound; tracked so the review sees what was measured.
- **The fixed notice for the partial month** instead of deriving it: M5's rule is 2.5's; the
  prototype only needs the page to have the notice somewhere.
